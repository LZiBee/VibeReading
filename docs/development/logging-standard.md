# 日志记录规范

本文档规定 AI 开发过程中的进度、报错和决策记录方式。所有日志默认使用中文，原始报错可以保留英文。

## 日志目录

```text
logs/
  progress/             每日开发进度
  errors/               每日错误和排查记录
  decisions/            架构决策和重要取舍
  archive/              归档日志
```

## 进度日志

保存位置：

```text
logs/progress/YYYY-MM-DD.md
```

记录时机：

- 开始一个开发任务时。
- 完成一个阶段性步骤时。
- 修改了重要文件后。
- 运行测试、构建、检查后。
- 本轮工作结束前。

进度日志模板：

```md
## HH:mm - 任务标题

- 目标：
- 状态：进行中 / 已完成 / 阻塞
- 已完成：
- 修改文件：
- 验证结果：
- 下一步：
```

要求：

- 写清楚“做了什么”和“为什么做”。
- 修改文件要写相对路径。
- 验证结果要写具体命令或检查方式。
- 如果没有完成，要写清楚阻塞原因和下一步。

## 报错日志

保存位置：

```text
logs/errors/YYYY-MM-DD.md
```

记录时机：

- 命令执行失败。
- 构建失败。
- 测试失败。
- 运行时报错。
- 类型检查失败。
- 依赖安装失败。
- AI 判断某个问题可能影响后续实现。

报错日志模板：

````md
## HH:mm - 错误标题

- 触发操作：
- 运行环境：
- 关联任务：
- 报错原文：

```text
在这里粘贴关键报错、堆栈或命令输出
```

- 初步判断：
- 排查过程：
- 处理结果：
- 关联文件：
- 后续动作：
````

要求：

- 报错原文保留关键内容，不要只写“失败了”。
- 如果报错包含 API Key、token、用户路径、论文原文路径，要先脱敏。
- 每个错误单独一节，不把多个错误混在一起。
- 修复后要补充“处理结果”。

## 决策日志

保存位置：

```text
logs/decisions/YYYY-MM-DD-简短标题.md
```

记录时机：

- 更换技术路线。
- 调整目录结构。
- 引入或移除关键依赖。
- 改变模块边界。
- 做出会影响后续开发方式的取舍。

决策日志模板：

```md
# 决策标题

- 日期：
- 状态：提议 / 已采用 / 已废弃
- 背景：
- 方案：
- 取舍原因：
- 影响范围：
- 后续动作：
```

## 敏感信息处理

日志中禁止明文记录：

- API Key、token、cookie、密钥。
- 用户真实隐私数据。
- 未公开论文全文内容。
- 本地绝对路径中的隐私部分。

脱敏示例：

```text
sk-真实密钥内容 -> sk-***已脱敏***
C:\Users\真实用户名\Documents\paper.pdf -> C:\Users\***\Documents\paper.pdf
```

## 每日最小记录要求

只要当天发生过开发行为，至少要有一条进度日志。

如果当天没有报错，不需要强行创建错误日志。若已经创建，可以写：

```text
今日暂无需要记录的报错。
```
