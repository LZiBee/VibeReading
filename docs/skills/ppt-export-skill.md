# PPT 导出 Skill 规范

本文件是产品内参考 skill，不是 Claude Code 原生 skill 安装包。它用于约束 `packages/ai` 生成 `DeckSpec` 的方式，并为 `packages/ppt` 导出 `.pptx` 提供稳定输入。

## 任务目标

从论文、笔记、AI 问答、截图和参考文献中生成一份可编辑的学术汇报 PPT。第一版默认生成 8 到 12 页中文汇报，适合组会、课程报告或论文阶段汇报。

## 输入材料

- 当前论文元数据：标题、作者、年份、摘要、关键词。
- PDF 来源片段：页码、原文、区域截图、图表截图。
- 结构化笔记：标题、段落、引用、公式、表格、截图。
- AI 问答：用户问题、AI 回答、来源引用。
- 参考文献：标题、作者、年份、DOI、来源页码。

## 输出约束

- 必须输出 `DeckSpec`，不直接输出 PowerPoint API 调用。
- 每页 `SlideSpec` 必须包含 `id`、`kind`、`title`、`elements` 和 `sourceRefs`。
- 每个来自论文、笔记、AI 回答或参考文献的关键结论都应保留 `SourceRef`。
- 每页正文不超过 5 个要点，每个要点优先控制在 28 个中文字符以内。
- 表格优先控制在 5 列、8 行以内；超过限制时改成摘要要点或拆页。
- 图片、公式和图示先转成 `SlideAssetRef`，再由导出器布局。

## 视觉与图片优先规则

- 组会汇报默认采用“视觉资产优先”：能用论文原图、图表截图、公式截图时，不用纯文字替代。
- 除封面、目录、参考文献和附录外，每个正文页都应尽量包含一个视觉元素：原图、截图、论文结构脑图、问题树、对比图或实验关系图。
- 视觉优先级：论文原图 / MinerU 图表截图 / 用户笔记截图 > 手工整理表格 > 自制 Mermaid 图示 > 纯文字。
- 不允许连续 3 页使用纯 bullet 版式；若没有原图，必须为背景、方法、实验、发现、讨论或总结页生成自制图示。
- 自制图示默认使用脑图：背景页用问题树，方法页用“模块/机制/输入输出/贡献”的结构脑图，实验页用“设置/基线/指标/发现”的验证脑图，总结页用 3 到 4 个分支的结论脑图。
- 只有当页面必须表达严格先后顺序、数据流或因果链时，才使用简单流程图；不要为了装饰生成线性流程图。
- 自制图示第一版优先使用简单 Mermaid `mindmap`，节点文案控制在 18 个中文字符以内，避免复杂嵌套；确需线性链路时才使用 `flowchart LR`。

## 推荐页型

1. 封面：论文题目、汇报主题、作者或汇报人。
2. 目录：研究背景、方法、结果、讨论和结论。
3. 背景：问题动机与研究空白。
4. 方法：核心方法、流程或模型结构。
5. 结果：关键实验、图表或对比。
6. 讨论：优势、局限和适用边界。
7. 结论：3 到 4 条可复述结论。
8. 参考文献：列出本次汇报实际引用的来源。

## 语言与风格

- 默认语言为中文。
- 学术汇报优先使用克制、清晰、可复述的表达。
- 避免把论文摘要原封不动塞入幻灯片。
- 避免使用没有来源的绝对化结论。

## 公式与图示

- 第一版公式可先作为文本或渲染图片处理。
- Mermaid、Graphviz、OMML 等高级能力按插件式后续接入。
- 若资产无法生成，应返回审计警告，而不是静默丢弃。

## 失败回退

- 大纲生成失败：回退为“背景 / 方法 / 结果 / 结论 / 参考文献”的固定骨架。
- 单页内容过长：优先压缩要点，其次拆成两页。
- 图片缺失：保留标题和图注，并生成 `missing-asset` 审计问题。
- 引用缺失：保留内容，但生成 `missing-source` 审计问题。

## 导出前审计清单

- 页面数量是否符合 `DeckIntent.targetSlideCount`。
- 封面、正文和参考文献页是否完整。
- 标题、要点、表格、图片是否超出版面预算。
- 每页是否至少有一个来源引用或明确标记为过渡页。
- 所有资产 ID 是否能解析到真实资源。
- 正文页是否尽量包含原图或自制图示。
- 是否存在连续 3 页纯 bullet 版式。
