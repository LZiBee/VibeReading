# 笔记系统实施方案

日期：2026-05-20

## 目标

把笔记从“可编辑文本”升级成“结构化、可追溯、可复用”的领域模块，支持模板、来源引用、回链、导出和后续数据库持久化。

## 当前策略

第一阶段先做“领域契约 + 模板注册 + UI 入口”，暂不把现有 Renderer 状态流立即切到数据库。

这样做的原因：

- 现有笔记工作流已经可用，先保持稳定。
- 模板、来源、回链这三件事可以先在领域层统一。
- 后续迁移到 `packages/db` 时，只需要替换存储实现，不需要重写模板和编辑逻辑。

## 实施顺序

1. `shared`
   - 扩展统一来源引用类型。
   - 让笔记来源可以指向 `note` / `note_block`。

2. `notes`
   - 建立模板注册表。
   - 提供模板列表、模板解析、模板创建入口。
   - 保持 `NoteDocument` 和 `NoteBlock` 作为核心结构。

3. `renderer`
   - 笔记模板选择页改成读取模板注册表。
   - 新建笔记入口支持 `freeform` / `paper_text` / `pdf_segment_screenshots`。

4. `db`
   - 补充 `note_templates`、`note_links`、`note_revisions` 等表。
   - 后续把模板配置、回链和历史版本落到本地数据库。

5. `workbench`
   - 统一命令、菜单和快捷键入口。
   - 让 PDF 选区、AI 回答、引用都可以直接生成结构化笔记块。

## 本阶段交付标准

- 能通过模板创建三类笔记。
- 每个笔记块都能挂来源引用。
- 模板信息由领域层提供，UI 不再硬编码模板文案。
- 当前状态保存逻辑先保留，避免一次性切换存储层。

## 下一步

先完成：

1. `shared` 的来源类型扩展。
2. `notes` 的模板注册表。
3. `renderer` 的模板选择页接入。
4. `db` 的基础迁移补齐。
